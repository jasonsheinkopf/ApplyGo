# Discovery Overview

ApplyGo begins with process discovery rather than framework selection. The purpose of this phase is to establish the real workflow, identify waste and risk, understand existing solutions, and define the product boundary before production code is written.

## Discovery questions

1. What work does a serious candidate repeatedly perform from career strategy through interview preparation?
2. Which steps create candidate value, and which are administrative waste?
3. Which steps are deterministic enough to automate, which require probabilistic assistance, and which require human judgment?
4. Which existing products solve individual steps well?
5. Which gaps remain when those products are combined?
6. Where must ApplyGo own persistent state and workflow control?
7. What deployment model can operate independently while remaining observable, secure, and recoverable?

## Deliverables

- problem and product thesis
- current-state and future-state value streams
- human/AI/system boundaries
- evidence-based market landscape
- capability and requirements map
- execution and deployment options
- initial recommendations and decision register
- phase exit criteria

## Guiding constraint

The project will be built. Discovery therefore does not ask whether the repository should cease to exist. It asks what custom system is justified, which components should be reused, and how to avoid building an expensive imitation of tools that already work.
