# Market Landscape

The market is broad but fragmented. Existing tools cluster around individual stages:

- job discovery and recommendations
- résumé and cover-letter preparation
- ATS optimization
- browser autofill and application assistance
- bulk or autonomous applications
- application tracking
- general-purpose browser agents

ApplyGo should not compete with every product feature-by-feature. Its opportunity is the persistent coordination layer across these stages.

## Working landscape

| Category | Representative approaches | Strong at | Typical gap relative to ApplyGo |
|---|---|---|---|
| Aggregators | LinkedIn, Indeed, niche boards | reach and alerts | incomplete official-source coverage, duplicates, limited user-owned state |
| Career-site monitoring | custom scrapers, alerts, feeds | source freshness | inconsistent ATS support, weak downstream workflow integration |
| Résumé tools | Teal, Jobscan, Rezi and similar | document optimization | disconnected from execution and outcome state |
| Application copilots | Simplify and browser autofill tools | form completion and in-browser convenience | limited orchestration, provenance, and provider control |
| Autonomous appliers | volume-oriented services and agents | reduced manual submission effort | transparency, quality control, policy fit, and account risk |
| General AI assistants | ChatGPT, Claude, Gemini | flexible reasoning and drafting | user remains the workflow and state manager |
| Browser-agent infrastructure | Playwright, browser-use, Stagehand, Steel | programmable web execution | not a job-search product; requires application policy and state |
| Trackers | spreadsheets, Huntr, Teal and similar | organization | limited end-to-end automation and execution recovery |

## Evaluation posture

A product that solves 80 percent of one stage may still be the correct integration. The custom-build case depends on the value of shared state, policy, and orchestration—not on claiming that every existing tool is inadequate.
